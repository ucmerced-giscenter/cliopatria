Developer documentation

The app is plain HTML, CSS, and JavaScript with locally vendored MapLibre GL JS 5.6.1 and PMTiles 4.3.0. Static per-year tiles provide display geometry. Anonymous ArcGIS queries provide search and attributes; ArcGIS prepares download files. No application backend or runtime build step is required.

API requirements

This section defines the services, parameters, responses, and failure behavior required by the current website. The browser talks directly to the public ArcGIS feature service. Map display uses PMTiles; research exports use the source feature service and retain whole polygons.

Access and service capabilities

  • The feature service and layer 0 must allow anonymous queries and extraction over HTTPS, with CORS permitting requests from the website. Data requests use credentials: 'omit' and do not send an ArcGIS account token.
  • The app requires Query and Extract, distinct Name queries for suggestions, ordered and paginated attribute queries, and the seven fields below. Before each export, it checks Extract and the requested format in supportedExportFormats.
  • Extraction uses syncModel=none. Editing and attachments are not required. The public Esri basemap key is a separate dependency; it is not used to authorize feature queries or downloads.

Metadata checked November 4, 2026: the service advertises Query and Extract, all four requested formats, and a 2,000-record query limit. Layer 0 supports pagination and ordering, has no attachments, and reports no timeInfo. Recheck these settings when replacing or republishing the source.

Requests and responses

Here, serviceUrl means the FeatureServer URL. ArcGIS metadata, query, and job requests include f=json. POST bodies are form-encoded with URLSearchParams; JSON-valued fields such as layerQueries are serialized inside that form body.

Search uses returnGeometry=false, the seven fields, resultRecordCount=25, and a changing resultOffset. Stable ordering is Name ASC,Year ASC,AreaSqKM DESC,OBJECTID ASC. Counts and IDs use returnCountOnly=true and returnIdsOnly=true. Feature extents use returnExtentOnly=true and outSR=4326. See the Esri Query reference.

Name suggestions use the same /0/query endpoint with outFields=Name, returnGeometry=false, returnDistinctValues=true, orderByFields=Name ASC, and resultRecordCount=12. Focusing or clicking the field requests names for the selected search scope, including an empty field. Null and empty names are excluded. The default list displays at most six names alphabetically. Typing updates matches after a 300 ms pause, with no minimum length; names starting with the input are preferred among the returned candidates. Superseded requests are aborted; suggestion requests time out after ten seconds. Choosing a suggestion runs the ordinary partial-name search. See Search instructions.

Selection and time rules

How each export scope becomes a filter
ScopeSelection rule
Selected featureFilter by the selected OBJECTID. Export one record, even when others share its Name and Year.
Current search resultsUse the submitted Name predicate and time scope. Include all matches, beyond the loaded search page.
Year or year rangeUse Year = 117 or inclusive bounds such as Year >= -3400 AND Year <= -1. Include available snapshots within those bounds.
Visible map extentCombine the time predicate with intersection against the map rectangle captured when Prepare download is pressed. Keep each intersecting polygon whole.
Entire datasetUse 1=1 for the count. Omit layerQueries and spatial filters from extraction.

Year is a snapshot field, not a start/end validity interval. Negative values mean BCE; there is no year zero. The app rejects zero endpoints, noninteger years, reversed ranges, and ranges outside the manifest. It does not interpolate geometry or use ArcGIS's time parameter. A range crossing BCE and CE includes existing panels on both sides.

For ordinary extents, the app first queries intersecting IDs using WGS84 envelopes and spatialRel=esriSpatialRelIntersects. Extraction then uses a native Web Mercator envelope with inSR=3857, keeping replicaSR=4326 for output. Native coordinates are necessary for this service's tested KMZ route; a WGS84 export filter produced an empty KMZ during validation. The filter selects whole polygons without clipping.

Antimeridian-crossing views use two ID queries and deduplicate results. Exact ID ranges and short IN lists describe that selection; oversized filters become numbered export parts. If every feature in the period intersects the view, the time predicate alone is sufficient. Later map movement does not alter an export already submitted.

How a download is prepared

  1. Capture and count the selection. prepareDownload() captures the scope, format, period, and selected feature or map bounds. It counts matches and reports an empty selection before starting a job.
  2. Check the service. exportFile() reads metadata and verifies extraction and format support.
  3. Submit the job. POST to /createReplica with the parameters below. Filtered exports include layerQueries; full-dataset exports omit it.
  4. Wait for completion. Follow the returned statusUrl, waiting two seconds between pending responses. The map remains usable.
  5. Display the file link. Validate the returned URL and assign it to the Download link. Numbered parts each receive a link when splitting was necessary.
  6. Download the file. Prepare download creates the link; the visitor then clicks Download. Generate it again if the temporary link expires.

This example requests all BCE panels as GeoJSON. These values become a URLSearchParams form body, not a raw JSON body. f=json controls the API response; dataFormat=geojson controls the downloadable file.

const parameters = {
  f: 'json',
  replicaName: 'cliopatria_export',
  layers: 0,
  syncModel: 'none',
  returnAttachments: false,
  replicaSR: 4326,
  dataFormat: 'geojson',
  transportType: 'esriTransportTypeUrl',
  async: true,
  layerQueries: JSON.stringify({
    '0': {
      where: 'Year >= -3400 AND Year <= -1',
      queryOption: 'useFilter',
      useGeometry: true
    }
  })
};

The initial response supplies a statusUrl. A completed job supplies status: 'Completed' and a resultUrl. Use the returned URLs; do not construct job or file paths. The tested public route requires no visitor login and creates no separate permanent ArcGIS Online content item. See the Esri Create Replica reference.

Errors and operational limits

  • Check HTTP success and any ArcGIS error object inside the JSON response. HTTP 200 alone does not mean success.
  • Export statuses Failed, CompletedWithErrors, Cancelled, and Canceled stop the wait and display an error. A completed response without a URL is also an error. Status and file URLs must use HTTPS and a hostname ending in .arcgis.com.
  • Search and feature lookups have 30-second client timeouts; export preparation has a 15-minute client timeout. Stop waiting aborts browser requests and polling, but does not cancel the Esri job.
  • Job duration varies; the polling delay is not a completion estimate. Errors require manual retry. The app does not automatically resubmit jobs or retain job history across reloads. Completed parts remain available if a later part fails.

Production checks should verify anonymous requests and CORS from the deployed origin, each format and scope, byte-range delivery, mobile behavior, and capacity under expected traffic. These requirements do not establish a high-traffic performance guarantee. A future queue, durable job history, or download-serving audit would require additional infrastructure.

Shape__Area and Shape__Length are service system fields, not substitutes for AreaSqKM. Dedicated alternate-name and region fields are absent. Name + Year is not a unique record key: several polygons can share both values.

Sample queries

Count the 3400 BCE panel · Get that panel as GeoJSON

For a range, use Year >= 1000 AND Year <= 1497. For search, use UPPER(Name) LIKE '%ROMAN%'. Escape apostrophes as doubled apostrophes and validate numeric IDs and years. The current Name filter retains SQL LIKE wildcards % and _. The helpers in js/lib/core.js build these predicates.

These direct query examples inspect a panel. For large downloads, use extraction. Paginate feature queries with a stable order, or query IDs; do not assume a single feature-set response contains every match.

Hosting and data releases

PMTiles hosting needs byte-range responses (206 Partial Content) with correct Content-Range. Separate tile hosting also needs CORS. Do not gzip whole PMTiles files at the HTTP layer. See PMTiles hosting documentation. For local testing, open index.html with Live Server.

Match the tile manifest and feature service to the same release. Rebuild after source revisions, especially OBJECTID renumbering. The selected record's year check cannot detect every source change. This folder contains the runnable website; preparation scripts and review reports are maintained separately.
